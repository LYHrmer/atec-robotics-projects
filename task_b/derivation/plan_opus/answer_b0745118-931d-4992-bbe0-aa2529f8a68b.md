**Structure**

- `PublicPlanarOdometry(dt=0.02)` — `dt` validated finite and positive in `__init__`.
- `reset()` takes no pose arguments: it sets XY to the module-level `SPAWN_XY = (-10., -10.)`, yaw 0, and clears `_prev_v_t`/`_prev_w`, `update_calls`, `integrated_intervals`, `path_length_m`.
- `update(proprio)` validates length 84, full finiteness, and `norm(gravity) >= 0.5` **before** any state write, then reads only `[0:3]`, `[3:6]`, `[9:12]`.
- Timing: the first call stores `v_t, w` and returns the spawn estimate untouched; each later call integrates the *previously stored* twist over one `dt`, then overwrites the store. `integrated_intervals` counts intervals, so `elapsed_s == integrated_intervals * dt` is 0 on call 1.
- Formula reproduced verbatim (gravity-projected `up`, tangential `v_t`, `w` about `up`, midpoint yaw, `Rz2(mid_yaw) @ v_t[:2]`, then `yaw += w*dt`). No filtering, bias, clipping or calibration.
- Atomicity: the advance is computed into locals (`xy`, `yaw_unwrapped`, `path_length`, `intervals`) and a finiteness check runs on those locals plus the new twist before anything is assigned, so overflow-producing input raises `ValueError` with the pose, history and counters unchanged.
- `position_xy` returns a copy; `yaw_rad` wraps via `(yaw+pi) % 2pi - pi` (yields `[-pi, pi)`); `yaw_unwrapped_rad` is continuous.
- `update()` returns `snapshot()`, freshly built each call with XY as a list, so a caller mutating the dict cannot reach internal state. `describe()` returns that snapshot plus the fixed-spawn source, input indices, the timing rule, the approximation text, and explicit claims: public-twist planar dead reckoning, no world-pose measurement, no uncertainty guarantee, no navigation/action logic, no auto-reset, and the 16.7/19.8 mm / ~0.008 rad figures labelled finite-run measurements.
- `target_body_xy(target_xy)` validates size 2 and finiteness, returns `Rz2(-yaw) @ (target - xy)`, stores nothing. The delivery center `(-3, -10)` and derived approach waypoints stay with the caller — the module holds no world or object map.

One note on a detail you specified: `path_length_m` sums `norm(previous v_t) * dt` using the full gravity-projected 3-vector, while the XY integration uses only `v_t[:2]`. On a tilted base those differ slightly, so path length is a marginally looser upper bound than the integrated track — I implemented it as written and documented it in `describe()` under `path_length_note`.
