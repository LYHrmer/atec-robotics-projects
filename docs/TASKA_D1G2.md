## 方法与训练

用户资料提供 D1+G2 模型和 D1 平地基础 ONNX。在基础策略上训练残差以适配完整机体和复杂地形，前置 RGB-D 导航给出速度与转向指令；G2 机械臂保持默认姿态。

| 项目 | 实际设置 |
| --- | --- |
| 算法 | 残差 PPO，基础 ONNX 固定 |
| 并行环境 | 512 |
| 训练 | 0–1999，共 2000 次迭代、24,576,000 个状态转移 |
| 阶段 | 混合地形 400 次、上台阶 1000 次、碎石专项 600 次 |
| 部署检查点 | model_1999_final.pt |
| 观测 | actor 331 维；critic 521 维 |
| 地形 | 训练 tile 8 m；原赛道 tile 20 m |

actor 由基础策略历史观测、机械臂关节状态、基础动作和上一残差构成输入。critic 额外看到用于训练的机身速度和地形高度；部署 actor 不接收这些特权输入。权重在完整评测中冻结。

导航使用 RGB-D、原始本体观测和已知固定赛道方向。世界位置、真值姿态与地形高度不进入 actor 或导航，仍用于原始终止、诊断和本地停滞看门狗。
通常速度为 0.6 m/s，已知碎石范围依据视觉相对位置降到 0.45 m/s。

最后台阶视场突变时，在同一坐标系下用原始观测的机身速度、角速度与重力进行短时积分，候选参考须连续两次通过视觉校验才接管。候选失配可以重建参考，但不清空预算。这不是纯视觉重定位，也未实现实机状态估计器。
最终两次重锚累计 **0.9 s、0.4844 m 路径积分**；单次上限 2 s/1 m，全程上限 4 次/4 s/2 m。路径积分是预算计量，不是定位误差。

## 从失败到通过

| 观察 | 修正或结论 |
| --- | --- |
| 旧推理后端的 BatchNormalization 与标准 ONNX Runtime 不同 | 最终基础策略改用数值对齐的 PyTorch 实现 |
| 原视觉方案走到 269.410 m 后卡台阶 | 近处特征消失，失联后零指令导致回滑；恢复旧图后仍卡住 |
| 恢复初版的候选也丢失对应关系 | 在同一预算内重建候选，避免始终保留过期参考 |
| 最后台阶诊断通过 | 109→131 m 用时 48.14 s；另做完整赛道验证 |
| 完整恢复配置第一轮失败 | 69.30 s 碎石翻倒；身体先失稳，视觉此前正常 |
| 第二轮完整通过 | 505.66 s，仅触发原始终点；完整轨迹、源码摘要与录像保留 |

Opus 参与故障时序、备用恢复原型和 CPU 检查；最终部署使用候选 RGB-D 参考重建，没有接入其备用继续行走原型。
同种子渲染仍存在像素微差，闭环路线和落足相位可能不同。当前证明一次本机通过，不能保证每次成功，也未完成官方在线验收。

## 复习与面试自测

1. 为什么用残差策略？说清已有平地能力、机械臂负载变化、样本成本和动作接口。
2. actor/critic 各看到什么？怎样核查训练特权信息没有误入部署 actor？
3. 为什么训练回报提高仍可能过不了长赛道？比较短回合和 286 m 连续任务，以及小概率失稳的累计影响。
4. 如何判定感知故障还是控制故障？用时间戳对齐接触、姿态、视觉状态和控制指令。
5. 为什么短时本体积分不能无限使用？解释坐标继承、漂移、预算和候选内部视觉一致性的能力边界。
6. 还缺哪些验证？冻结策略后的多次/多种子试验、实机状态估计、标定、执行器差异与延迟。这些不能写成已完成。
