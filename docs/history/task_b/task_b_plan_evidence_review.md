## 3. 适合写进执行方案的阶段门槛

以下为下一步执行方案建议，不是本次已运行的结果。

1. **冻结基线与 CPU 预检。** 保留 11 个结果及两个未完成/集成失败目录；新建输出目录。记录确切源码哈希、CLI、原始 Task B 配置和资产状态。CPU 回放重点验证公共观测顺序、近场微进的边界、静止检测新鲜度、超时及回退行为。一个新进程只跑一个回合。
2. **验证近场进入。** seed 42、compact+stance hold、与候选相同的轮速增益先跑。目标是在 5,000 步上限内真实进入 `CREEP_WITHIN_ARM_WINDOW` 并使目标前向距离持续下降，最终进入 x≤0.525 m、|y|<0.22 m 的刹车窗口。只用公共视觉决定是否微进；诊断真值仅用于事后分析。若 10 秒内目标距离不减、失去视野或触发非法接触，结束本轮并定位，不直接增大全部轮速或延长同一无效命令。
3. **验证静止观测与可达性。** 停轮至少 1 秒；上述速度门槛连续满足至少 0.2 秒；记录静止之后至少两次新的有效 RGB-D 检测，建议其目标估计差<0.04 m。若弹簧回弹使 x>0.55 m，则有限次重新微进；避免永久 BRAKE。可达性候选应显式输出预测距离，不因 IK 返回结果就记成功。
4. **验证实际伸手。** 先用 `--reach_lowering 0` 隔离机械臂能否进入并保持 `REACH`、实际关节是否收敛、是否发生机身/腿部非法接触。以公共 q/qdot 控制，以记录的真实 `gripper_base`-物体 3D 距离分析误差；失败时区分视觉误差、IK 几何极限、关节跟踪与底盘漂移。
5. **再验证小幅下降。** 仅在伸手已收敛且实际距离接近阈值时，比较 0、0.02、0.03 m 静态下降候选，每个配置独立新进程。正式计分线是≤0.20 m；规划最好留约 0.02 m 余量。3 cm 只是允许的候选上限，不能直接承诺正分；发现接触/倾斜应停止继续下降并按经过验证的恢复策略处理。
6. **首次正分证据审核与复现。** 官方原始分数>0、与各奖励分量相符、对应事件状态满足实际阈值、没有更早终止、没有真值进入策略。正分后 100 步观察窗口记录行为；当前 `score_hold_steps` 仅延长运行而不冻结策略，不能称为“静止保持 2 秒”。同配置另开进程做同 seed 复现；其他 seed 成功率作为独立泛化指标，不把一次成功扩写成稳定通关。
7. **GitHub 交付。** 审核通过的代码、准确的状态说明、结果 JSON/配置/哈希与正分视频再发布；验证远端 commit 与 release 资产、视频可播。零分视频全部留本地，保留旧 A/E 视频。

## 4. 发布证据必须防止的误判

- 本地官方 `env_cfg.py` 明确 `gripper_base` 到物体根节点三维距离≤0.20 m、每个物体首次计 +1；这不证明夹住。入圈每个物体首次 +1；必须另查 18 个物体同时在圆内的完成条件，不能以历史累计分数代替完成条件。
- `env.reward` 含 `step_dt`，累计时只除一次。`RewardManager.get_active_iterable_terms` 已去掉 dt；再除会夸大 50 倍。要求结果中的 reward-term 与 env 累计误差检查通过。
- `trace.jsonl` 与 `telemetry.npz` 中机体/末端/物体位置来自动作前，奖励来自动作后。不能用同一行的动作前距离否决或证明该步奖励；应读 `scoring_events.json` 的动作后状态，终止步读 reset 前捕获。
- 当 `state_timing=missing_terminal_capture` 时，事件证据不完整；不能用重置后的默认关节或最终 PNG 补证明。`final` 和周期截图在终止发生时可能来自重置后的观测，不能作为得分瞬间图。
- 首次奖励事件需要确认对应物体此前未计数；接近、入圈分别维护去重集合。一物体已被靠近，重复靠近不会继续加分。
- 发生正分与非法接触同一步，应同时报告，不作为稳定正分候选。缺 `result.json` 的中断运行不能补成完整零分回合。
- `source_manifest.json` 只覆盖加载的部分 Python 源码，不覆盖 USD/材质资产、驱动、Isaac 包或运行时 monkeypatch，也不证明本地原仓库与上游一致。发布时需附本任务原配置/资产的独立检查，并如实说明相机兼容补丁；不要写“所有官方资产已被源码哈希证明未修改”。
- GPU 串行，Claude 做可独立交付的 CPU 分析/控制状态机/证据工具，root 负责集成与唯一 GPU 跑分，独立审查代理核对结果。明确 Claude 的真实调用记录与 CPU/实测边界。
