# ATEC Task B：从已验证抓持推进到首次真实投递

制定时间：2026-09-14。依据桌面的 Claude 执行汇总、当前生产代码、p13 原始记录，以及 GPT-6-Astra（ultra）与两项独立复核。**本轮交付是下一轮执行方案，没有运行新的 GPU 实验，也没有完成投递。**

## 结论与主线

保留已经成功的抓取和载荷跟踪，把主要工作转向**载物移动、制动、桶边定位和释放**。现在不把 RL/IL 训练作为首次投递的前置条件。

确定主线为：

**正常闭夹 → A 高举并稳住 → A 姿态持载移动 → 桶外预停 → 制动与转向 → 侧方精停 → B 侧摆 → C 越沿 → D 桶内适度低放 → 张手 → 连续观察 → 独立确认同一物体实际入桶。**

先跑一次有明确目的的短程持载试验，证明底盘能带着瓶子移动和停止；通过后进入完整投递回合。不要反复运行已完成的原地 A/B/C 来累计“成功次数”，也不要改走多接近分路线。

## 已复核的事实，以及汇总中需要修正的解释

1. **抓持进展成立，投递仍为 0。** p13 已由冻结的 `audit_positive.py` 重新核验，122 项检查通过，包括原源码、原评分、终止条件、源快照和实际奖励几何。结果是 1 个接近分、0 投递。完整运行没有原始终止或截断。
2. **“解析轮控不能移动”不成立。** 当前 p13 从原出生点到抓取位置净移动约 **2.983 m**，使用的是现有 compact 站姿、姿态保持和轮驱动。旧 F22/F0.8 是更早的不同站姿/控制配置，不能证明当前方法或持载运动绝对不可行；不过当前数据尚未证明带瓶移动。
3. **两帧速度平均是新的判定方法，不能称验收完全没变。** 它抑制了交替高频分量，但也可能隐藏真实高频运动。位置摆幅小不等于速度小：旧侧摆末段的位置总变差约 **0.040–0.041 rad/s**，不是 0.0016。本轮控制间隔 .02 s、物理间隔 .005 s，瞬时 qdot 与跨四物理步的位置差分不必相等。PhysX 官方也解释了 TGS 子步报告速度与整步速度可能不同，不能据差异直接判定传感器错误。[官方说明，第 5 页](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/_downloads/6acf3afb8f69452757e0e766b5a22978/implicitDrives.pdf)
4. **低频振荡确实被明显压下，但理论解释要收敛。** 1.67 Hz 模型里的惯量由观测频率拟合，不能再当作独立预测证明；q2 前馈近零，其他轴并非全部为零。保留有效的低增益、阻尼、滤波和积分组合，不恢复旧的大增益。
5. **跟随审计有基线标签错误，但修正后仍证明抓起。** p13 报告称以 CONTACT_OPEN 为基线，实际取了 step3544 的 PAYLOAD_RAISE。真正 CONTACT_OPEN 是 step2921；两者物体根移动约 3.205 mm，瓶底差约 -0.014 mm，修正不推翻抓持。以后从嵌套 child_phase/child_state 找真正准备前帧，并排除 terminated、truncated 和非法接触。
6. **不能把 root 漂移当整瓶形状误差。** 44.5 s 的 root 相对夹爪漂移为 16.6 mm，但物体还有旋转；独立重算发现整段相对转角可达约 17.5°、完整 mesh 顶点偏移可达约 47.6 mm。A 完成之后的 B/C 段仍有约 13° 相对转动、35.0 mm 对应顶点位移，不能全部归因于刚抬起时的调整。停止后的最后 HOLD 则明显稳定。以后几何净空审核必须同时考虑平移和转动，并以实际静稳后的握持关系为基准。

## 第二阶段：一次短程持载机动试验

先用原 seed42、新进程、新输出目录，运行正常抓取和 A 高举；在原抓取位置完成：

1. 静稳持载，记录 A 到位后的公开基线。
2. 缓慢前进 **0.20–0.30 m**，名义速度先 **.03–.04 m/s**，随后制动并重新稳定。
3. 做约 **+10° / -10°** 的有界转向检查，中间分别制动；只在公开 RGB-D 确认的近场可行区域执行。不追求精确回到原世界坐标。
4. 停住后保持至少 2 s，由独立审计检查整瓶离地/跟随、姿态、原终止、实际移动、停止距离和正反转向响应。

这些是新试验初值，不是已验证性能。机身姿态硬保护保留；移动期间不能要求身体永远满足原地静止速度门，但必须有独立的最大速度、偏航率、夹持丢失、关节偏差、进展不足和总时限保护。

**轮命令单位必须先理清。** 当前 evaluator 先乘 `wheel_action_gain=8`，原轮 action scale 再乘 5，因此策略输出的 wheel 数值最终相当于 **乘 40 得到 rad/s**。`.05` 的归一化动作不是 `.05 m/s`。新底盘模块建议统一输出物理轮目标，再只在一个明确边界换算；用实际 schema、左右关节名和最终 actuator target 做审计，避免重复乘增益。速度与转向响应使用公开 twist 反馈，不能把理想无滑移差速模型当成实测响应。

**制动要独立成阶段。** 先减速，再判断实际切向速度/偏航率与静稳窗口；确认稳定后才建立新的静止位移预算与轮位置锚。不要重复“还在 .235 m/s 滑行便启用 .03 m 静止预算”的错误。记录响应延迟和停止距离，以此确定导航提前制动距离。

短试验失败时只做有依据的有限修正：

- 轮子响应不足但机身和夹持稳定：检查最终动作是否被 holder 覆盖、速度单位、左右符号以及滑移，再调整有界轮速补偿。
- 主要是机身姿态/接地问题：成功接近时腿参考是 compact，抓持后额外降低了 .04 m 名义参考。可先在 A 闭环持载、轮锚保持下，缓慢撤回两层降低恢复原 compact，再静稳验证和重做短测；不要直接猛加轮速。
- 转向弱但能稳定前进：优先有限曲率弧线和减少总转角的停靠路线。若当前站姿和恢复 compact 后均没有可用的持载移动响应，再核验是否存在匹配 B2wPiper 的现成 locomotion checkpoint。不要把 Task A 的 45 维网络强行补零接到 84 维输入，也不要把从零 RL/IL 训练默认为下一分钟就能完成的步骤。

## 第三阶段：带误差预算去桶边

`PublicPlanarOdometry` 从回合第一帧起每个控制步调用一次，使用原公开出生点 (-10,-10,yaw0)，不能抓起后才初始化，也不能用 GT 校正。

已知静态桶心 `c=(-3,-10)`。初始侧停候选：

```
n = normalize(p_est - c)
t = R90(n)
p_dock = c + 1.45*n
p_pre  = p_dock - 1.0*t
最终底盘朝向 t，桶在 body +Y。
```

最近侧停方向并非一定最快。用当前公开里程计、实测转向能力与公开近场障碍，比较少量候选桶外方向；代价同时考虑路长、总转角和制动/整车净空，不按 seed 写死路线。预停点处转向，再短直行到侧停点，避免贴桶转动车身。

导航速度先以短测证据为准，通常从 `.04–.05 m/s` 开始，`.08 m/s` 只作为尚待实测的候选上限。阶段时限按真实路长、已测最低有效速度、总转角和制动时间计算，不能沿用原地 payload 的短时限，也不能无进展无限延期。episode 总步数要容纳完整路线，但不得超过原任务 1200 s 限制。

旧两回合约 17 mm 的里程计误差不能直接当作未来长程持载导航误差保证。当前 head 相机向下看，腕相机可能被瓶子遮挡；不要假设全程都能看见桶，不强加 SLAM。桶进入真实可见范围后，可用公开 RGB-D 和原圆柱/桶沿几何做近端相对距离/方向核验；转成切向后允许短时间视野外的有限里程计推进。若末端定位误差无法约束到净空预算内，先停住补测/重新观测，不能盲目伸臂。

## 第四阶段：沿用 B/C，新增经过净空审核的 D 低放

独立 CPU 已按 **p13 实际物体/夹爪/底盘姿态、原 8377 个瓶体顶点和机器人碰撞几何**重算。以下全部是原地记录向假想桶边位置的几何核验，**不是已经在桶边成功执行**：

| 项目 | 约值 |
|---|---:|
| 底盘距桶心 | 1.45 m |
| C 末端整瓶最外径向距离 | .90855 m |
| C 末端瓶底世界高度 | .62120 m |
| 已记录 EXTEND 过程中最低瓶底 | .61206 m |
| 相对 .55 m 桶沿的全过程最低余量 | 62.1 mm |
| 车体/轮子到外墙支持面最小余量 | 约 74–75 mm |

桶内壁是 32 段多边形；保守孔内半径为 `.98*cos(pi/32)=.97528 m`，不能只按 .98 圆计算。平移、偏航、夹持转动和执行误差需要一起扣除。**XY 30 mm + yaw .05 rad + 额外 20 mm 夹持平移的旧组合已不能保证余量为正。** 20 mm 的 root 漂移更不能替代整瓶顶点误差。

首轮可把约 **XY≤20 mm、yaw≤.02 rad** 作为停靠设计目标，但必须依据传感器/短测和新的形状误差预算核验，不能把 odom 自己报“到点”当成真实精度已满足。B/C 过程中保持轮锚，只有真实关节到位并稳住后再执行下一段。

释放前考虑 D 低放。保持当前 C 的水平位置 `[.2,.52]` 和方向，公开关节作 IK seed，将末端 body z 从约 `.40` 分阶段降到 `.35`，再到 `.25`。初步 CPU 原限 IK 与路径采样成功：

- body z=.35：瓶底约 .57195 m，手指最低约 .69380 m。
- body z=.25：瓶底约 .47220 m，手指最低约 .59405 m，仍高于桶沿。

这降低自由落下高度，同时保留手指在沿上方的余量。必须审核新实际握持关系、完整路径和误差包络后才执行，不能把静态成功当作自动放行。闭指的 IK 与路径采样尚不覆盖开指到 70 mm 的完整扫掠，必须在真实释放前补这一项 CPU 几何检查。暂不采用更深的未经充分验证插入；body z=.05 的深放候选存在机械臂碰壁风险，应拒绝。

**桶底顶面为世界 z≈.05 m，不是 .095 m。** 当前 C 直接张手相当于瓶底下落约 .571 m；D=.25 后约 .422 m。先前实际读回的物体材料恢复系数为 1，桶地形配置也有高恢复设置，因此需要检验反弹；多体接触下的有效反弹不能只由这一个参数确定。低放只减少风险，不保证留下。禁止修改恢复系数来制造成功。

## 第五阶段：释放与真正的投递验收

- 新增明确 `OPEN` 阶段。保持末端目标、载荷跟踪器和轮锚，按每指 `.05 m/s` 将当前预载命令缓慢移向 `[+.035,-.035]`。
- 当前命令可能仍为 `[-.075,+.075]`，命令本身走完约需 **2.2 s**，不能给 1 s 的张开截止。随后还需实测开口达到要求和连续观察；采用分别计时的初值：OPEN 最多 6 s、观察最多 5 s（其中连续有效观察至少 3 s），总预算 11 s。
- 只有明确进入有准入条件的 OPEN 后，才关闭“空夹说明掉物”的搬运看门狗；其余姿态、非有限值、关节硬限、轮锚和原任务保护保留。
- 张开后按时间戳连续观察至少 **3 s**；应记录反弹、瓶子卡在夹爪、墙外落地和退出桶的情况，必要时延长有限观察来判定稳定性，不立即撤臂扫碰瓶子。
- 策略只声明 `release_sequence_complete`，不以奖励或 GT 推进状态。
- 独立审计关联此前被夹持的**同一物体**，确认原 `objects_in_circle` 首次事件、真实落入实体桶、后续持续在圈内及无原始失败。D 下放较深时，物体仍被夹持就可能先触发 `objects_in_circle`；因此必须继续完成真实张手与留桶观察。仅出现 +1 接近分、持夹跨入圈或单帧跨入圈，均不能描述为稳定投递完成。
