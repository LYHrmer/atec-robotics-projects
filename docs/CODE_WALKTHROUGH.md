# 跟着一次控制调用读懂 Task E

[项目导读](LEARNING_GUIDE.md) · [算法原理](ALGORITHM.md) · [动手练习](HANDS_ON.md)

这套程序每次接收图像、关节反馈和累计得分，返回下一步关节位置指令。阅读时可以追踪一个具体动作：看见瓶子、移到上方、下降夹紧，再抬过篮沿。下面按这条数据流解释当前入口。

## 先跟完一次调用

[solution.py](../solution.py#L16) 的 `AlgSolution` 继承了另一份同名类。Python 实际的方法查找顺序，即 MRO，是：

```text
solution.AlgSolution
→ solution_baseline.AlgSolution
→ task_e_held_motion.HeldMotionMixin
→ solution_task_e_rgbd.AlgSolution
→ solution_task_e_vision.AlgSolution
→ object
```

`super()` 沿这个顺序寻找下一个实现。创建对象时，实际进入 RGB-D 类的构造函数，把 `estimate_grasp_contacts` 作为感知函数交给视觉基类；基类的 `self.reset()` 又会调用最外层重写的 `reset`。几层方法合作清空任务记录、下降历史和夹宽历史。这里重置的是控制器变量，机械臂随后通过 `INIT` 移向默认关节姿态。

一次 `predicts(obs, current_score)` 先经过入口的提前确认条件，再进入[视觉基类的 `predicts`](../solution_task_e_vision.py#L222)。基类读取关节、更新计数，根据当前状态选择动作，最后返回字典。代码里的 `self._plan_motion(...)` 仍会从最外层类开始查找，因此同一段状态机可以使用不同物体的规划逻辑。

还要注意“当前状态”和“正在规划的动作”不是同一件事。例如在 `CLOSE` 内规划下一段抬升，规划成功后才切到 `LIFT`；在 `VERIFY_LIFT` 内规划搬运，成功后才切到 `TRANSPORT`。几个子类正是利用调用发生时的状态拦截规划。如果把这些判断直接改成目标状态名，程序反而不会进入物体专用分支。

`total_steps` 记录实际调用次数；`state_step` 记录当前状态经过几步。提速入口在条件满足时，临时把后者推到原基类的确认门槛，仍让基类检查得分和切换状态，不增加得分。正常切换由 `_set_state` 清零状态计数；如果没有切换，`finally` 会恢复实际经过的步数。

## 输入如何变成接触点

单环境 `obs["proprio"]` 通常是 `(1, 24)`：前 8 项是相对默认值的关节位置，中间 8 项是相对默认速度的关节速度，最后 8 项是上一次动作。本任务默认速度全为零，因此中间八项数值就是实际关节速度。当前控制主要读取前 8 项，不能把整个数组当成 24 个关节。前六个位置用弧度、后两个夹爪位置用米，相应速度单位为 rad/s、m/s。[`joints_from_proprio`](../task_e_geometry.py#L300) 加回默认位置；按手臂和夹爪拆开写是：

```math
q_{\mathrm{arm},0}=[0,\ 1.2,\ -1.5,\ 0,\ 1.2,\ 0].
```

```math
q_{\mathrm{jaws},0}=[0.035,\ -0.035].
```

两段合起来就是 `DEFAULT_JOINT_POS`，下文记为 $`q_{\mathrm{default}}`$。

输出的 `action` 是长度为 8 的列表，评测器再转成 `(1, 8)`；`giveup` 是布尔值。[动作换算](../task_e_geometry.py#L305) 为 $`a=(q_{\mathrm{target}}-q_{\mathrm{default}})/0.5`$，所以全零动作表示默认姿态。

**例一：观测与动作换算。** 以下是教学输入，不是一次实测抓取：

```python
import numpy as np
from task_e_geometry import joints_from_proprio, action_from_joint_targets
proprio = np.zeros(24)
proprio[1] = 0.1
target = joints_from_proprio(proprio)
target[6:] = [-0.025, 0.025]
print(action_from_joint_targets(target))
```

第二关节恢复为 $`1.2+0.1=1.3`$ rad，输出为 `[0, 0.2, 0, 0, 0, 0, -0.12, 0.12]`。夹爪指令是瓶子的闭合目标；实际手指受到物体和关节限位阻挡，目标越过闭合位置用于产生夹持力，不表示物理关节已经到达负开度。

图像位于 `obs["image"]`：RGB 通常为 `(1, 480, 640, 3)`，深度为 `(1, 480, 640, 1)`。当前决策使用固定相机 `video_rgb/video_depth`，没有调用末端相机定位。[`_images`](../task_e_perception.py#L45) 去除单环境维度，也兼容 RGBA、通道在前的 RGB 和没有 RGB 的深度输入。

[`unproject_depth`](../task_e_geometry.py#L262) 丢弃零、NaN 和无穷深度。深度 $`d`$ 是沿相机光轴的距离；设像素列、行为 $`u,v`$，先得到相机坐标，再用外参转到世界坐标：

```math
p_c=d\begin{bmatrix}
(u-c_x)/f_x\\
(v-c_y)/f_y\\
1
\end{bmatrix}.
```

```math
p_w=R_{wc}p_c+t_{wc}.
```

**例二：一个深度像素的往返。** 当前 640×480 标定给出 $`f_x=f_y=732.999284`$ 像素，主点为 `(320, 240)`。构造中心像素深度 1.4 m：

```python
import numpy as np
from task_e_geometry import unproject_depth, project_world
depth = np.full((480, 640), np.nan)
depth[240, 320] = 1.4
points = unproject_depth(depth)
print(points, project_world(points))
```

计算得到世界点约 `[0.96450799, 0, 0.84951901]` m；投影回去是 `(320, 240)`、深度 1.4 m。这验证的是坐标换算，不代表识别出物体。数组索引是 `[行, 列]`；`project_world` 返回的却是 `(列, 行)`。

识别在 [`estimate_objects_detailed`](../task_e_perception.py#L127) 中继续。世界坐标布尔掩码保留 X 为 0.77–1.23 m、Y 为 −0.10–0.44 m、Z 为桌面以上 9–245 mm 的区域，排除桌面、篮区与底座。点云按 4 mm 体素取代表点，连接距离不超过 9 mm 的邻点形成连通簇，少于 50 个原始点的簇被丢弃。

每簇通过 PCA 求水平长短轴，再计算长、宽、高，与三种物体的尺寸模板比较。`linear_sum_assignment` 做整体分配，避免一个簇重复分给不同物体；代价大于 7 的配对不接受。RGB 经 3×3 中值滤波后，黄色比例只略微支持瓶子和香蕉的匹配，颜色没有替代几何分割。字典键 1、2、3 分别对应糖盒、瓶子、香蕉；缺失目标会被省略。

此时还应继续读 RGB-D 层的 `estimate_grasp_contacts`：它拿到检测诊断里的可见边界和点数，再覆盖瓶子、香蕉的基础接触估计。基础感知文件中的 `_contact_position` 因而不是这两个物体最终下发的抓点。检测点数不足或尺寸不可信时，这一层会删掉对应目标；控制器需要重新观察，不会用出生位置补上一个看似完整的结果。

## 接触点如何变成关节目标

感知返回手指夹持接触点 $`c`$，而 [`fk`](../task_e_geometry.py#L59) 返回夹爪基座 `gripper_base` 的 4×4 世界变换。函数从固定基座开始，依次应用六个关节的固定平移、固定旋转和局部 Z 轴转角。前六个关节决定此变换，夹爪开度不改变它。可选返回的 6×6 雅可比，上三行为位置变化、下三行为旋转变化。

这些关节固定变换来自模型，运行时不需要再加载 USD。位置统一在世界坐标中；几何模块保存的四元数顺序为实部在前，交给 SciPy 时会显式换成实部在后。相机也有轴约定转换：反投影先使用右、下、前的光学坐标，再转到世界坐标。把四元数顺序或相机轴当成通用约定，是比公式计算本身更常见的错误来源。

用 $`r_z`$ 表示旋转矩阵第三列，即手指伸出方向，代码中写作 `R[:,2]`。接触深度取 0.115 m，因此当前夹持点为：

```math
c=p+0.115r_z.
```

给定目标朝向的第三列 $`r_z^\star`$，末端目标位置为：

```math
p_{\mathrm{target}}=c-0.115r_z^\star.
```

[`solve_ik`](../task_e_geometry.py#L107) 用 SciPy `least_squares` 在六个关节上下限内寻找关节角。它最小化下面残差的平方和，其中 `rotvec` 用方向表示旋转轴、长度表示旋转角：

```math
r(q)=\begin{bmatrix}
p(q)-p_d\\
w\,\mathrm{rotvec}\left(R(q)R_d^\mathsf{T}\right)
\end{bmatrix}.
```

默认旋转权重 $`w=0.20`$，成功容差是位置小于 5 mm、角度小于 0.08 rad；目标没有旋转时只优化位置。[`solve_grasp_ik`](../task_e_geometry.py#L194) 枚举倾角和夹爪方向的正负，先检查手指盒到桌面的间隙，再用 $`w=0.15`$、3 mm/0.05 rad 容差求解。两个夹爪方向虽能夹同一个物体，却可能受有限腕关节范围影响而具有不同可达性。

这里有两层判据：抓取求解器可能返回“最接近的候选”，其 `success` 未必为真；[通用 `_plan_motion`](../solution_task_e_vision.py#L109) 最终按 18 mm/0.18 rad 的较宽误差门槛决定接收。读代码应跟到调用者，不能只看 `IKResult.success`。通用规划把接触点直线分段，默认间距 25 mm、最多 32 点，逐点把上一个解作为下一个初值。

[`_motion_command`](../solution_task_e_vision.py#L143) 根据实测关节逐点推进：普通/慢速中间点容差为 0.04/0.025 rad，最终要求连续 12 步误差小于 0.025 rad。目标是“当前关节加限幅误差”，普通/慢速限幅为 0.085/0.035 rad。这是目标位置差，不能直接当速度或加速度。文件中的 `differential_ik` 是另一个可用工具，当前状态机没有调用它。

## 三种物体怎样走过状态机

`INIT` 至少等待 80 步且回零误差小于 0.04 rad 后进入 `LOCATE`。定位每 5 步采样一次，至少 16 步后按瓶子、糖盒、香蕉的顺序选目标；至少三次检测才计算中位接触点，水平极差超过 45 mm 会重新采样。随后 `PREGRASP` 移到接触点上方 12 cm，`DESCEND` 下降，`CLOSE` 夹紧，接着抬升、确认、搬运、放置、开爪和回撤。

物体差异主要集中在 [`solution_task_e_rgbd.py`](../solution_task_e_rgbd.py#L20)。瓶子从可见顶部附近点云重新估计瓶盖中心，将接触高度放在顶部以下 35 mm。提起和搬运的接触高度提高到桌面以上 0.36 m，让悬垂瓶身越过篮沿；持物动作目标差另限制为 0.025 rad。

香蕉使用可见包围盒的 `lowerX + 0.053`，Y 中心减 4 mm，高度为桌面加 25.5 mm，避免把视觉弯曲空隙当成可夹区域。下降时保留无遮挡阶段的估计。[`_plan_gentle_lift`](../solution_task_e_rgbd.py#L76) 每约 7 mm 高度求一次 IK，前 6 cm 不增加水平位移，再逐步向机器人方向增加最多 55 mm 位移；姿态从实测旋转出发，每段尝试保留当前倾角或增加 1°、2°，总增量不超过 35°。它使用更严格的 2 mm/0.025 rad 容差，香蕉抬升和搬运也使用慢速执行。

糖盒的搬运、放置通过 [`solution_baseline.py`](../solution_baseline.py#L12) 调用 [`HeldMotionMixin`](../task_e_held_motion.py#L27)，位置线性插值、姿态用 `Slerp` 插值。完整路径才会安装：相邻关节目标差不超过 0.30 rad，中间点接触误差/角误差不超过 15 mm/0.12 rad，终点为 10 mm/0.10 rad；还检查桌面间隙。当前入口又把糖盒开爪后的回撤交给它，失败则退回通用规划。保持当前姿态是候选之一，并非每条路径都锁死旋转。

下降迟迟不到目标时，RGB-D 类检查最近 35 步的关节极差；至少下降 90 步、极差小于 0.020 rad，且接触点水平误差小于 25 mm、高度误差在 −10 至 85 mm 内，才允许按接触停滞结束下降。这解释了为什么“没精确到达 IK 点”仍可能开始夹紧。

入口的提前确认也依赖观测：CLOSE 最少 35 步且十次夹宽极差小于 1.5 mm；VERIFY_LIFT 最少 10 步且新增抓取分到位、夹宽大于 6 mm；OPEN 最少 20 步且夹宽大于 65 mm；VERIFY_PLACE 最少 10 步且本次所需得分到位。首次完整抓放需要 6 分，已记过抓起分的重试只需新增 3 分。条件不满足时仍等待原门槛；闭空、规划失败和运动超时进入原恢复流程，尝试次数有上限。

本机任务每控制步为 0.02 秒，因此 35 步是 0.70 秒，不能把状态计数直接读成秒。运动超过 700 步会触发超时处理；每个目标的尝试计数上限为 3。定位长期缺失也会消耗尝试次数，所以这个上限不是承诺每个物体一定执行三次闭夹。

几何可达和桌面间隙检查不是完整避障，也不保证摩擦夹持成功。公开累计分数不带物体身份，状态机依赖顺序操作解释它；官方终止可能发生在最后一个物体尚未松开的 `PLACE` 阶段，终止后的开夹留篮检查由评测器单独记录。七个运行时策略文件不读取场景物体真值，评测轨迹中的真实位置也没有传回策略。
