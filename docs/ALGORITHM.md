# 从 RGB-D 到三物体抓放：算法与实验说明

这个项目在 ATEC 2026 Task E 固定基机械臂仿真任务中，用 RGB-D 感知、机器人运动学和反馈状态机完成三物体抓取、搬运与入篮。它是一个针对已知任务配置的几何控制方案，没有训练新的强化学习或模仿学习模型。

开发采用 AI 辅助编程与诊断。持物姿态连续规划 helper 的初稿由 Claude Opus 参与生成，随后结合代码检查、运动学检查和物理仿真验证。结果归属于保存下来的具体源码版本，不把 AI 生成代码本身当作算法正确性的证据。

## 任务、观测与信息边界

任务中有糖盒、芥末瓶和香蕉，固定基 Piper 机械臂包含 6 个臂关节与 2 个夹爪关节。每个物体首次抓起得 3 分、首次进入篮区再得 3 分，总分 18；全部物体处于有效篮区时环境结束。

策略使用以下公开输入：

- 24 维本体观测：相对关节位置 8 维、关节速度 8 维、上一步动作 8 维。
- 固定外部相机的 `video_rgb`、`video_depth`。接口还提供末端 RGB-D，但当前策略没有把末端图像用于抓取决策；开发时曾用它诊断可见性，实际夹持部位有时不在画面中。
- 当前累计得分，用于确认抓起和放置事件。

部署策略不访问仿真场景对象、物体真实位姿、评测日志或奖励管理器。机器人尺寸、关节轴、默认姿态、相机标定和固定桌篮配置来自公开任务定义，是离线已知参数。随机物体的抓取位置由当前图像估计，不读取种子，也不把标称出生坐标当成检测结果。

开发期间使用过仿真真值做离线故障诊断，例如对比物体与夹爪的相对运动；这些数据不进入策略，也不属于公开推理代码的运行依赖。

## 1. RGB-D 感知：输出可夹持点

`task_e_perception.py` 从外部相机图像提取桌面上的物体候选。流程为：

1. 按已知相机内参将深度反投影，并转换到任务世界坐标。
2. 保留桌面上方、源物体工作区内的有效点，排除大部分桌面、底座与篮区。
3. 将点云体素化，用空间近邻建立连通分量。
4. 根据点数、空间范围、PCA 形状与弱颜色特征，为糖盒、瓶子、香蕉匹配候选；用一对一分配避免同一簇被重复识别。
5. 输出物体对应的抓取接触点与诊断信息。检测不到时不补造坐标。

对相机光学坐标中的像素 `(u,v)` 和图像平面深度 `d`，基础反投影为：

```text
p_camera = d * K^-1 * [u, v, 1]^T
p_world  = R_world_camera * p_camera + t_world_camera
```

实现同时处理相机轴约定与图像布局。深度的定义、相机坐标轴和相机位姿必须一致；只把 RGB 画出来并不能证明点云的世界坐标正确。

采用三维连通分量的原因是，糖盒和瓶子在二维图像中可能投影重叠。二维颜色区域容易将它们粘在一起，而真实深度仍有间隔。颜色只作辅助，形状与深度是主要证据。

感知返回的是适合手指夹持的表面附近点，不是物体根位置。例如瓶子遮挡糖盒近侧时，可见糖盒的中心会偏向远侧；只要点仍落在可夹持盒体内，就不必先恢复完整物体中心。

当前方法使用已知物体和固定任务配置的几何先验。它不是类别无关的抓取网络，现有模板对平躺瓶子、复杂遮挡或额外物体的恢复能力有限。

## 2. 运动学：接触点不等于末端原点

`task_e_geometry.py` 保存从公开机器人定义导出的运动学常量，实现正运动学 FK、逆运动学 IK、关节观测还原和动作尺度换算，运行时不依赖仿真 SDK 或 USD 文件。

设末端原点位置为 `p`、旋转为 `R`、手指接触点相对末端沿本地 Z 方向距离为 `l`，则：

```text
contact = p + l * R[:, 2]
p_goal  = contact_goal - l * R_goal[:, 2]
```

如果直接把视觉接触点作为末端原点目标，夹爪座和手指会到达错误高度。这是视觉与执行之间需要明确的几何关系。

IK 用有界非线性最小二乘同时减小位置误差和姿态误差，关节限制来自机器人定义。轨迹由接触空间的中间点组成，每个点以上一个关节解为初值，减少跳到另一条关节分支的机会。执行时继续比较实际关节反馈与目标，并限制每步关节变化。

官方动作是带默认姿态偏置的关节位置命令，scale 为 0.5：

```text
q_actual = proprio[:8] + q_default
action   = (q_target - q_default) / 0.5
```

官方默认 `clip=None`，因此动作值可能超过 1；不能把连续动作一律理解成 `[-1,1]` 的归一化量。关节可达范围和轨迹限速在各自环节处理。

## 3. 反馈状态机：每一段动作都有验证条件

`solution_task_e_vision.py` 管理以下流程，`solution_task_e_rgbd.py` 加入物体专属修正：

```text
初始化 → 定位 → 预抓取 → 下降 → 闭爪 → 抬升检查
       → 搬运 → 放置 → 张爪 → 放置检查 → 回撤/下一物体
```

主要逻辑包括：

- 高位获取多帧检测，降低操作过程中夹爪遮挡造成的定位偏差。
- 接近阶段用关节反馈判断路径是否到达；持续停滞且接触位置合理时，允许从下降转入闭爪。
- 抬升后结合得分增量和夹爪开度判断是否持有物体。开度非零只能说明存在约束，不能单独证明已经抓起。
- 放置后等待新的入篮计分，再确认完成。当前桌面检测区域不覆盖篮内，不能把“桌上看不到”直接当成成功入篮。
- 失败时回撤、回到观察姿态并进行有限次数的重试，避免无限等待。

这仍是针对任务的有限状态控制器，没有全局搜索所有抓取顺序和无碰撞路径。使用得分确认是该比赛公开接口允许的反馈；迁移到真实机器人时，需要视觉、触觉或力反馈替代这一确认信号。

## 4. 关键失败与修正

### 瓶子：低位搬运撞到篮沿

最初的瓶子方案可以抓起，却在横向搬运时失持。只降低关节速度没有解决问题。

离线诊断发现，进入篮沿之前，瓶子相对于夹爪的位置基本稳定；接近前壁后才突然滑动。该区间腕部姿态只变化约 4.8°，不像突然腕翻转。RGB-D 显示旧路径中瓶底约低于篮沿 31 mm，支持“瓶身碰篮沿”的判断。

修正分为两处：通过 RGB-D 瓶盖区域定位瓶颈，减少夹爪座先碰瓶盖的情况；把持瓶时的接触轨迹从桌面上方 0.27 m 提高到 0.36 m，使悬垂瓶身先越过篮沿，再横移放置。减速失败、高位路径成功的对照支持这一解释，但没有宣称做过全部因素的系统消融。

### 香蕉：碰撞几何、夹持杠杆与初段姿态

香蕉的可视表面有弯曲空隙，碰撞几何则不能只按可见纹理理解。夹爪的有限厚度会同时覆盖一段香蕉；视觉上可夹的细处，不代表整个手指厚度范围都能可靠闭合。

早期靠端点的抓取一度让香蕉离桌，但抓取点距物体根部较远，抬升时香蕉逐渐转动并沿手指滑出。修正将接触点向中部移动、略微降低，并改变刚闭爪后的提升路径：先竖直提升，再只施加 IK 可达所需的小幅连续倾斜。该组合在 v1 完整任务中拿到香蕉的抓取与入篮分。

这些接触偏置针对已知香蕉资产和当前摆放分布。能完成一个初态，不代表对任意香蕉姿态都有效；也不能从组合成功反推出每个参数的独立贡献。

### 持糖盒搬运：可达端点之间仍可能腕跳变

两个端点都能解出 IK，不代表中间关节路径适合持物。糖盒的搬运和下降引入 `task_e_held_motion.py`，把当前位置姿态与候选目标姿态连续连接：

1. 枚举有限的夹爪方向、倾角和偏航候选。
2. 对接触位置作插值，对旋转使用 Slerp。
3. 逐点求 IK，检查接触误差、姿态误差、手指与桌面的间隙、关节限制和相邻关节跳变量。
4. 仅安装完整通过的路径，按最大关节变化、总关节行程和旋转幅度选择候选。

该 helper 由 Claude Opus 参与编写，经过审查后用于糖盒搬运与放置，在 seed 0 的完整任务中达到 18 分。它检查运动学连续性与桌面间隙，不是通用碰撞检测器；篮沿和其他物体的避碰仍依赖路径目标设计与物理评测。

## 5. 先证明观测有效，再评价控制算法

本机 Isaac Sim 4.5 与所用 IsaacLab 组合出现过相机同步问题：机器人在物理张量中已经运动，但 RGB-D 仍显示初始场景。旧的零分运行因此不能作为策略能力基线。

有效评测保留原生 Fabric，并在本地评测进程适配相机位姿读取。通过机器人运动、物体落稳后的深度变化和 FK 对照确认观测链路。该修复属于本机评测基础设施，不进入独立策略包，也不修改机器人或物体物理参数。

这是项目中重要的实验方法：先区分传感链路、运动学、接触、计分四个环节的问题，再修改对应环节。否则可能把渲染故障误认为视觉失效，或把碰篮沿误认为夹持力不足。

## 复现与下一步

满分运行保存了策略源码快照及 SHA256，独立包从这些快照构建。部署接口已做独立导入、批量张量转 NumPy、八维有限动作和 JSON 返回检查；未把“可以导入”当作物理成功。

公开仓库提供自行实现的控制代码、算法说明和演示材料，不附带官方资产、完整仿真环境源码或私人诊断日志。运行者需要依照赛事官方渠道另行准备环境与资产。

下一步最有价值的工作是：对同一个冻结版本预先确定种子集合，报告逐种子得分与失败类型；对瓶高位路径、香蕉接触点与提升姿态做针对性消融；补齐失败后再定位和重新抓取能力。只有这些证据充分后，才讨论成功率和泛化范围。
