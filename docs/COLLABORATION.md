# 分工与实验验收

本轮目标是完成 Task A 的可核验比较，并实际推进 Task B。各模块有独立负责人，最终行为由原始环境的运行记录决定。

| 工作线 | 实际职责 | 交付与验收 |
| --- | --- | --- |
| Claude Opus：Task B 初始实现 | 编写静止、轮驱、转向、下蹲控制与独立评测入口 | `task_b/control.py`、`evaluate.py`；首轮到达调用预算后已写出四个文件，随后由主代理修复并运行，不能把该轮视作完整验收通过 |
| Claude Opus：稳定控制 | 根据真实转向/下蹲失败实现轮速限制、倾斜反馈与小幅伸腿补偿，提出可证伪预测 | `task_b/stability.py`、`STABILITY_DESIGN.md`；真实 CLI 调用成功完成，随后做 CPU 边界审计和 GPU 对照 |
| Claude Opus：实测反馈后的迭代 | 根据正常站姿触发限速的问题，实现冻结参考站姿与独立绝对倾角检查 | `task_b/stability_profiles.py`；第二次调用成功完成，初次 18 项 CPU 检查与真实转向回合已执行；发布前边界补丁后共 21 项通过 |
| 独立审查与视觉实现 | 核对真实 Isaac 动作消费端、复位语义、连续轮限位；实现移动 Piper FK/IK 与合法 RGB-D 接近 | `diagnostics.py`、`arm_kinematics.py`、`visual_approach.py` 和 CPU 审计报告 |
| 主代理 | 分配互不冲突的文件、集成接口、串行使用单张 GPU、保存所有结果和录像、更新展示与 GitHub | 固定 seed 42，保留失败；避免把未运行的代码或少量存活测试说成通关 |

策略只接收允许的本体与相机观测及静态结构信息。物体/根位姿、接触力用于单独记录与离线诊断，不输入导航或动作生成。源码哈希、观测关节映射一致性、奖励口径和终止前记录用于追踪每一轮实际运行。

稳定模块的候选、边界修复和参数迭代按版本保留；限速后未跌倒不等于有效转向。抓取奖励中的“接近”也不等于物理夹持，Task B 的通关仍要求原始成功条件。
