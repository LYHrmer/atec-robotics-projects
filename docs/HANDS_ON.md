# 不启动仿真，也能把几个关键步骤跑一遍

[项目导读](LEARNING_GUIDE.md) · [算法原理](ALGORITHM.md) · [代码导读](CODE_WALKTHROUGH.md) · [自测题](SELF_CHECK.md)

这些练习直接调用仓库里的几何函数，只需要 Python、NumPy 和 SciPy。前四个使用人工构造的数据，便于检查计算过程；最后一个读取已有实测结果。它们不产生新的比赛成绩。

在仓库根目录运行下面的命令，可以依次看到五组输出。已有 Isaac Lab 环境时，也可以把 `python3` 换成该环境的 Python 路径；不需要启动 Isaac Sim。

```bash
python3 tools/task_e/learn_geometry.py
```

脚本只有一个文件：[learn_geometry.py](../tools/task_e/learn_geometry.py)。每个小节也可以单独运行。建议先按文字手算，再看输出；遇到不一致时，先检查坐标系和单位。

## 1. 把一个像素送到世界坐标，再投影回来

```bash
python3 tools/task_e/learn_geometry.py camera
```

这组练习构造一张 640×480 深度图，仅在第 240 行、第 400 列放入 1 m 深度，其余像素设为无效。相机参数沿用项目的真实标定常量，但这张深度图是人工输入。

主点是第 320 列、第 240 行，水平焦距约为 732.999 像素。有效像素比主点向右偏了 80 像素，因此相机坐标中的横向位置为：

$$
x_c=\frac{(400-320)\times1}{732.999}\approx0.109141\,\mathrm{m}.
$$

同理，$y_c=0$、$z_c=1\,\mathrm{m}$。经过外参转换，程序得到世界坐标约为 `[0.631791, -0.109141, 1.071554]` m。随后再投影回图像，结果应为 `[400, 240]`，光轴深度仍为 1 m。

这次往返说明投影和反投影在同一套标定下相互一致。它不能单独证明相机标定与真实场景相符；两个函数共同使用错误外参时，往返也可能成立。对照仿真中的已知位置或独立测量，才能检查标定本身。

再想一步：把这个像素移到图像中心，保持 1 m 深度，相机坐标中的横向分量应变成多少。这里不需要重新求 IK，只涉及相机几何。

## 2. 同一个夹持点，为什么有不同的末端位置

```bash
python3 tools/task_e/learn_geometry.py contact
```

人工夹持点设在 `[1.05, 0.18, 0.886643]` m。竖直向下时，末端原点只需在它上方 0.115 m，约为 `[1.05, 0.18, 1.001643]` m。

将夹爪绕世界 Y 轴转过 20° 后，接近方向变成约 `[-0.342020, 0, -0.939693]`。为了让手指仍对准同一点，末端原点必须同时改变水平位置和高度，约为 `[1.089332, 0.18, 0.994707]` m。

可以在纸上画两条长度相同、方向不同的线段，让它们的下端落在同一个夹持点。上端就是两种末端原点位置。这个图对应公式 $p=c-lRe_z$，也解释了为什么倾斜抓取不能只给高度加一个常数。

该练习只检查几何关系，没有给这个人工目标做可达性和碰撞检查。

## 3. 用 FK 构造一个可达目标，再让 IK 找回来

```bash
python3 tools/task_e/learn_geometry.py ik
```

脚本先取六个合法关节角 `[0.10, 1.25, -1.47, 0.02, 1.12, 0.06]` rad，用 FK 算出末端位姿，再从默认关节姿态出发求 IK。因为目标由这台机器人的 FK 产生，至少已知存在一组解。

重点看输出的位置误差和朝向误差，而不是只看六个角度是否逐项相等。一般情况下，IK 可能找到另一组到达同一位姿的关节角。本机这组简单算例的两种误差都约为 $10^{-9}$，更换库版本时末位数值可以不同；实际控制仍按代码设置的接受阈值判断。

把“由 FK 构造目标”改成“随便指定一个很远的坐标”，就失去了已知可达的前提。此时求解器能返回一组数值，也不意味着目标已经达到，还要看误差和 `success`。

## 4. 分别还原观测和换算动作

```bash
python3 tools/task_e/learn_geometry.py action
```

第二臂关节默认角度是 1.2 rad。如果希望它到 1.3 rad，动作分量应为：

$$
a_2=\frac{1.3-1.2}{0.5}=0.2.
$$

如果本体观测中的第二项相对位置是 0.04，那么实际关节角是 1.24 rad。这是读取反馈的换算，与前面的目标动作是两件事：一个说明“希望去哪”，另一个说明“现在在哪”。

两者之间还有跟踪误差。位置命令发出后，关节需要时间运动，也可能受到碰撞阻挡，所以状态机不能只在发送命令后机械地等待固定几帧。

## 5. 从结果文件重算时间和腕部行程

```bash
python3 tools/task_e/learn_geometry.py metrics
```

这一组读取真实 seed 42 对比结果，预期输出为：

| 指标 | 基线 → 加速版 | 相对变化 |
| --- | --- | ---: |
| 仿真完成时间 | 61.84 → 53.78 s | −13.03% |
| 腕关节总行程 | 9.65516 → 8.26540 rad | −14.39% |
| 全程差分加速度 RMS | 3.33555 → 3.48109 rad/s² | +4.36% |

百分比统一按“新版减基线，再除以基线”计算。负号表示下降，正号表示上升。这里可以同时看到收益和取舍：少等待、少转腕之后，全程加速度 RMS 并没有一起下降。

这条命令只重算汇总数据。如果想从逐步关节数据重新开始，运行：

```bash
python3 tools/task_e/compare_motion.py \
  results/baseline42_motion results/fast42_motion \
  --relative-to . --output-dir runs/my_comparison
```

然后打开 `runs/my_comparison/comparison.md`，找到糖盒的 `RETRACT` 和 `HOME` 两行。回撤省下的时间，有一部分花在了之后回观察位；把两行相加，才能解释净收益。更完整的分段分析见 [优化记录](OPTIMIZATION.md)。

做完这些练习，可以回到一帧抓取画面，把像素、世界夹持点、末端原点、关节目标和实测关节位置依次指出来。能分清这五个量，再读控制器中的条件分支会容易很多。
