## 当前实现合同与实测验收

静止视觉确认只使用停稳后的新检测，清除运动期旧目标；无公开帧号时按原相机更新周期限速计数，并明确这是更新周期假设。反复读取同一控制时刻、目标过期、来源变化或新点不一致，不能保留旧授权。

轮保持模块输入四个公开轮角与轮速，采用 wrapped angle error，输出四轮同号的物理角速度。参数为 `dt=.02`、`kp=2`、`kd=.25`、上限 `.6 rad/s`、变化率 `2 rad/s²`；集成层在原 wheel gain 和站姿处理之后用物理速度除动作 scale 覆盖轮切片，避免重复放大。P2 的 620 个激活样本重放通过，连续锚点未改变。

已确认的伸臂只使用一个固定关节目标；局部视觉候选不重新求 IK，不作为下探许可。公开速度超过原阈值时有限暂停，关节进展、姿态、累计平移 / yaw / 重力方向和总时限持续生效。P1 settle 的最终 104 个合格样本首末覆盖 2.06 秒，才形成进入小幅下降的依据。

## 未采纳建议：类别误判与非公开控制输入

实际 Claude Opus 的早期只读设计把 sugar 与 mustard 编号顺序翻反，并据初始生成高度断言历史一直追踪不可得分的糖盒。该结论与官方配置不符，已拒绝采纳。

| --- | --- | ---: | ---: |
| object_1..6 | Sugar_cfg → `004_sugar_box.usd` | 0.15 m | 约 0.090206 m |
| object_7..12 | Mustard_cfg → `006_mustard_bottle.usd` | 0.10 m | 约 0.140224 m |
| object_13..18 | Banana_cfg → `011_banana.usd` | 0.10 m | 约 0.060087 m |

依据是官方 `tasks/task_b/env_cfg.py` 与 `assets/objects/task_b/object.py`。初始元数据中的高度属于物体尚未落稳的状态，不能代替稳定后的根高度，更不能凭高度推断类别。

同期复核 `first_reach_side_seed42_01` 第 5000 步：视觉表面点世界坐标约 `(-6.7299845,-8.6845309,.1971712)` m，object_10 根位置约 `(-6.7238097,-8.6802740,.1402248)` m，水平相差 7.50 mm，三维相差 57.44 mm。目标确实对应芥末瓶；可见表面高于根位置，不能将这一差值直接解释成视觉误差。该关联只用于离线审查，控制器不读取 object_10 编号或真值。

因此没有换追 object_1..6，也没有用初始高度强制淘汰当前目标。读取 `illegal_force` 或 `scoring_events` 来决定动作的建议同样拒绝；低臂扫掠暂未采用。首分后的评测停止读取奖励，但奖励不返回策略，二者职责不同。

## 后续决策原则

第一分成立后，优先保留可复现的当前基准，再分别验证物理夹持、抬升和投递。每项新许可都需要对应阶段的实际观测依据，不自动把接近阶段的不可观测运动许可扩展到运输。静态估算可以决定下一次有界实验，实际成绩只能由新回合和原始奖励证明。

GitHub 展示当前经核验的最好成绩；未来更高分通过验收后更新对应展示与视频。较低分结果和原片本机归档，当前旧数据与 Git 历史保留；不为扩大展示而把近场接近写成抓起或通关。
