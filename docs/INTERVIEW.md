# 面试讲解提纲

这份提纲帮助解释项目中的问题、证据与取舍。讲解应与真实参与范围一致：项目采用 AI 辅助开发，部分代码初稿来自 Codex 与 Claude Opus；不要把协作生成的代码说成全部独立手写，也不要把尚未完成的验证说成已有经验。

## 一分钟介绍

> 这个项目针对 ATEC 的桌面三物体抓放任务。策略使用外部相机 RGB-D、机械臂关节观测和当前分数，输出八维关节位置控制量。我采用几何感知、FK/IK 和反馈状态机，并用 AI 辅助实现和诊断。过程中最关键的工作是把失败分清楚：先修正相机与物理不同步的问题，再识别瓶身碰篮沿、香蕉夹持后滑出，以及持物搬运时的姿态连续性。连续姿态版本在 seed 0 得到本机 18 分；相同运行代码的独立包在 seed 42 再次得到 18 分，并录制了完整视频。验证覆盖仍然有限，还没有证明在大量随机初态上稳定成功。

讲解时补充两个状态：远侧香蕉实验分支 far5 在 seed 5 得到 15/18，未完成三物体任务；该分支不同于当前 v2，不纳入 v2 的成功率统计。独立 v2 包的 seed 42 冷启动录像已完成：18/18，3092 步，61.84 秒仿真时间。

接口提供两路 RGB-D，当前抓取决策实际使用固定外部相机，未融合末端图像。当前仓库入口是 [solution.py](../solution.py)，它组合了 [RGB-D 控制器](../solution_task_e_rgbd.py) 与 [持物姿态规划](../task_e_held_motion.py)；完整文件对应关系见 [算法说明](./ALGORITHM.md)。这些都是仓库相对路径。

## 五分钟讲解顺序

1. **定义任务与证据。** 三个物体，每个抓起与入篮各 3 分，总分 18；指出视频对应的代码版本和种子，以真实评测结果证明完成。
2. **解释输入怎样变成动作。** RGB-D 反投影、三维连通簇识别、抓取接触点、接触点到末端目标的变换、IK 和动作尺度。
3. **讲一个最有证据的故障。** 优先讲瓶子：抓起成功、减速无效、篮沿处相对滑动、提高悬垂瓶身净空后成功。
4. **解释反馈和失败处理。** 下降停滞如何判断、为什么非零开度不等于可靠抓取、怎样用公开分数确认、失败如何回撤。
5. **主动说明边界。** 固定物体与相机配置、特定初态结果、没有新 RL 训练、没有新的官网成绩，下一步如何验证同一版本的稳定性。

## 常见追问

### 为什么没有直接训练强化学习？

该任务的机器人、物体种类和相机标定已知，几何控制能较快建立可解释、可逐段验证的基线。本项目没有训练新的 RL 或 ACT 模型，也没有把历史权重当作本轮成果。

这不是证明几何控制普遍优于学习方法。如果增加物体种类、旋转变化、遮挡和恢复需求，可能需要学习式感知或抓取选择。比较两条路线时，应在相同环境、种子集合和计时方式下比较成功率、开发成本与推理成本。

### “纯观测”为什么还能用机器人尺寸和桌篮坐标？

需要区分固定公开参数和运行时隐藏状态。运动学参数、相机标定、固定桌篮配置来自公开任务定义；随机物体的当前位置由图像估计。策略不读取场景对象的真实位姿、种子或评测日志。

这属于带任务先验的观测控制，不是无标定或未知环境的通用抓取。开发时的真值诊断只帮助解释失败，不进入部署算法。

### 怎样从图像得到机械臂目标？

先根据深度与内参得到相机坐标，再用外参变换到世界坐标；在物体簇中选择可夹持点。随后减去末端原点到手指接触处的姿态相关偏移，才得到 IK 的末端位置目标。

可以现场画出相机、世界、末端三个坐标系，并解释：接触点相同而姿态不同，末端原点目标也会不同。

### 为什么采用三维连通簇，而不只按 RGB 颜色分割？

瓶子和糖盒可能在图像中相互遮挡，二维区域连通并不意味着属于同一物体。深度可以利用空间间隔拆开候选；再结合形状与弱颜色特征进行匹配。代价是依赖已知尺寸与较干净的深度，对接触粘连、躺倒或完全遮挡仍会失败。

### 如何证明瓶子是碰到篮沿，而不是动作太快？

证据链包括：抓起后早段相对位姿稳定，接近篮沿时才滑动；相机估计瓶底低于篮沿；单独减速仍失败；抬高搬运轨迹后完成入篮。

这支持碰撞解释，比只看一张失败图更可靠。但应承认尚未做完整因素消融，不能说所有速度与摩擦影响都被严格排除。

### 香蕉为什么比盒子难抓？

可视形状弯曲，碰撞几何和手指有限厚度共同决定实际接触；端部抓取容易形成较大杠杆，初段姿态变化又可能让它沿手指滑出。方案把抓取点向中部调整，并先竖直提升、再连续小幅倾斜。

讲解时要承认这些偏置针对已知资产，不能把一次调参成功包装成通用抓取理论。后续应分别验证接触点和提升姿态两个因素。

### IK 的每个点都可达，为什么还会搬运失败？

多个关节分支可能到达同一末端位姿，逐点求解可能跳到另一分支；即使位置误差小，腕部大幅变化仍会扰动物体。连续持物 helper 对位置和旋转同时插值，检查全路径的关节跳变量、误差和桌面间隙，只接受完整路径。

该方法仍不等于完整避障规划，未检查所有物体间碰撞。这也解释了为什么瓶子的高位净空路径仍需单独设计。

### 为什么不把 action 限制在 `[-1,1]`？

动作不是天然具有该范围的概率或归一化控制量。官方位置控制采用 `q_target=q_default+0.5*action`，默认不裁剪；如果额外截断到 `[-1,1]`，将改变实际关节目标。应按官方动作定义、机器人关节限制与执行限速分别处理。

### 为什么用得分判断成功？真实机器人怎么办？

当前分数是官方向策略开放的反馈，可以用于确认抓起与入篮事件。夹爪开度和图像只能提供不完全证据，得分能减少状态机过早确认。

真实机器人没有比赛得分接口，需要另建成功判据，例如篮内视觉检测、触觉或力反馈。不能直接把这里的“分数确认”当作真实机器人通用方案。

### 视频是否足以证明算法成功？

视频便于解释动作和失败，但不代替计分与代码版本。应给出视频对应的种子、冻结源码、哈希与评测结果。两个不同版本分别成功，不等于一个版本在两个种子上都成功；未完成的测试不计入成功率。

seed 42 包录像已完成 18/18，发布的入口和依赖均有哈希可核对。far5 的 15 分作为独立实验分支失败记录保留，用来说明远端持物搬运与恢复问题；它不属于 v2 的重复试验统计。

### AI 参与了哪些工作，如何体现个人能力？

如实说明 AI 参与代码初稿、候选方案与诊断，连续持物规划 helper 有 Claude Opus 参与。技术能力应通过能够解释和验证这些代码体现：说清坐标变换、动作尺度、失败判据和实验结论，能定位错误并复现结果，而不是靠隐去协作过程。

如果某个模块目前还不能解释，应在面试前补做推导和复现，不把“能调用代码”说成“已掌握算法”。

## 建议现场展示

- 播放一段三物体成功视频，说明对应版本与种子。
- 打开 [solution.py](../solution.py) 与 [状态机](../solution_task_e_vision.py)，指出公开输入、动作出口和成功确认条件。
- 用一个接触点演示 `p_goal=contact_goal-l*R[:,2]`，解释偏移方向。
- 解释瓶子低位搬运失败与高位路径的因果证据。
- 查看冻结源码与校验文件，说明如何避免“展示的是旧视频、运行的是新代码”。

演示前应自己完成一次从独立目录导入、运行与核对结果的复现，并能回答：更换种子、相机标定错误、物体检测缺失、IK 不可达时分别会发生什么。
