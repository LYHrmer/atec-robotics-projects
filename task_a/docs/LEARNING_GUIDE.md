# 先看懂机器人为什么能走，再看 PPO

[项目首页](../../README.md) · [运行 Task A](../README.md) · [代码与面试自测](../../docs/TASKA_D1G2.md)

## 机器人每一步要解决两个问题

第一个问题是“往哪里走”。前置相机看到路面，程序估计已经走了多远、是否偏离方向，再给出前进速度和转向指令。
第二个问题是“腿和轮子怎么动”。行走策略读取这些指令和关节等反馈，输出下一步动作。

这里把两件事分开处理：相机不直接决定每个关节的动作，行走网络也不直接吞入原始图片。

```text
RGB-D 图像 → 估计位移和航向 → 前进、转向指令
                                  ↓
                  关节等反馈 → 基础策略 + 学到的修正 → 动作
                                  ↑                    ↓
                                  └──── 新的反馈 ────────┘
```

这个循环持续执行，直到原任务报告到达终点，或者发生非法接触、跌落、超时等结束条件。最终的“通关”来自环境判定，不由视频标题或导航估计宣布。

## 为什么不直接使用现成模型

用户资料里有一个能让 D1 在平地行走的 ONNX 模型。但本次机器人还带着 G2 机械臂，要经过碎石、坡地和台阶；原来的动作未必能适应完整机体。

项目保留这个基础模型，另外训练一个网络，学习怎样修正基础动作。这就是**残差策略**。它利用已有的行走能力，同时需要重新检查完整机器人上的稳定性和动作尺度。
机械臂在这里保持默认姿态；这项任务没有训练它去抓取物体。

## 六个术语，用这个项目理解

| 术语 | 在这里指什么 |
| --- | --- |
| 基础策略 | 已有的 D1 平地行走模型，训练残差时保持固定 |
| 残差 | 另一个网络学到的动作修正；与基础动作组合后控制机器人 |
| PPO | 用仿真采样和奖励更新策略的方法，不是机器人硬件或导航模块 |
| actor | 真正运行时输出动作的网络 |
| critic | 训练时帮助估计价值的网络；它可以看到一些部署 actor 看不到的训练信息 |
| 视觉重锚 | 旧画面无法继续匹配后，建立新参考并接回同一估计坐标系 |

理解这些含义后，再看输入的维数：部署 actor 为 331 维，critic 为 521 维。后者额外使用训练中的机身速度和地形高度信息；它们没有作为部署 actor 的额外输入。

## 训练结果和通关结果有什么区别

训练使用 512 个并行环境，共 2000 次迭代。先练混合地形，再练上台阶，最后加强碎石路，保存 `model_1999_final.pt`。
训练地形块长 8 m，完整赛道由 20 m 地形块组成。能在训练短回合拿到高奖励，不等于能连续走完 286 m。

因此每次完整验收都冻结权重，从原始起点开始，保留原终止条件。当前有一次 505.66 s 的完整通过，同配置上一轮仍在碎石路翻倒。不能用一次通过估算稳定成功率。

## 最后台阶为什么曾经卡住

相机越过台阶边缘时，近处竖直表面突然从画面中消失，变成远处路面。图像和深度仍然存在，但旧的对应特征没有了。
原先的视觉保护长时间输出零指令，机器人在迈步中停住并回滑；后来虽然重新看见旧特征，机体已经卡在不利姿态。

修正后的程序保留旧参考尝试恢复，同时建立候选新参考。新参考必须连续两次通过视觉校验才接管；候选也失配时可重建，但不能清空时间和距离预算。
没有视觉对应的短间隔，只能靠本体观测做短时积分，所以要如实记录其来源和误差风险，不能把它称为纯视觉定位。

最终完整通过里，两次恢复累计 0.9 s、0.4844 m 路径积分。这个距离是预算消耗，不是“误差只有 0.4844 m”。

## 跟着真实数据读一次

1. 打开 [结果摘要](../evidence/acceptance_summary.json)，先核对起点、终点、用时和唯一终止项。
2. 看 [实验对照](../evidence/README.md)，区分完整赛道、末段诊断、启动短测；局部成功不能拼成全程通过。
3. 读 [残差模型接口](../tools/d1g2_taska_residual.py)，追踪观测怎样变成动作。
4. 读 [运行入口](../tools/run_d1g2_taska.py)，找出导航、动作、环境步进和终止记录的顺序。
5. 最后读 [恢复模块](../tools/d1g2_taska_visual_recovery.py)，检查重建参考时哪些状态更新、哪些预算必须保留。

没有 GPU 也可以阅读这些证据和代码；运行仿真时再按 [使用说明](../README.md) 配置环境。想进一步检验理解，回答 [面试自测](../../docs/TASKA_D1G2.md) 中的问题。
